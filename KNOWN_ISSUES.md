# Known Issues

Bugs and gaps found during work on this codebase, logged rather than fixed inline so refactor/feature commits stay reviewable. One entry per issue: location, what's wrong, why it wasn't fixed on the spot.

## Product decision on record

- **The standing snapshot ingestion job described in `action-plan-v2.md` (Risk 1, Phase 1, Phase 8's prerequisite) is shelved, not deferred.** Decided 2026-08-05: this tool is used for one-off, prompt-driven discovery across unrelated topics, not repeated observation of a fixed portfolio — there's no stable "watchlist" for a background poller to revisit. A scheduler solves a problem this product doesn't have. `decayLabelFor`/`dependencyHealthFor` (`src/domain/usecases/ScoreAndRank.ts`) computing from live, single-point signals (current push/release date, current dependency files) rather than historical deltas is therefore the *intended* design, not a gap waiting on a prerequisite — the product's own review of stars vs. README quality is meant to happen live, at query time, using whatever a fresh GitHub call returns right now.
- **`action-plan-v2.md` itself is now stale against this decision** — it still describes the ingestion job as required groundwork (Risk 1, Phase 1, Phase 8, Phase 12's "Day 2: start snapshot ingestion job running"). Left as-is for now rather than rewritten unilaterally, since it's the project's plan-of-record document and rewriting the phases that depend on it (8, 9, 12, 13) is a real editing decision, not a mechanical sync. Anyone reading it today would believe the ingestion job is still planned.
- **`OwnerProfile`, `DependencyMap`, `WatchTarget`, `WatchSubscription`, `NotificationEvent`, `SearchHistory`, `TrendSnapshot`** (`prisma/schema.prisma`) — all migrated, zero code references any of them. `WatchTarget`/`WatchSubscription`/`NotificationEvent` specifically depend on the shelved ingestion job and should be considered shelved along with it, not just "not yet built." `OwnerProfile`, `DependencyMap`, and `SearchHistory` don't share that dependency and remain open, independently-scoped features.

## Docs / config

- **`--trends` flag** — documented as a goal in `action-plan-v2.md` Phase 11, does not exist in `src/cli/index.ts`. `--explain` does exist and works. Depended on `TrendSnapshot`, which depended on the now-shelved ingestion job — this flag is shelved along with it, not just blocked.
- **Spikes A/B/C** (`action-plan-v2.md`, prerequisites for Phase 1) — README-quality-scoring calibration, dependency-data-source validation, and intent-classification-accuracy testing were never formally run as the structured exercises the plan describes. `reports/SEARCH_CRITERIA_REVIEW_2026-03-30.md` and `reports/SEARCH_AND_NOTIFICATIONS_BRAINSTORM_2026-04-01.md` cover adjacent ground informally but aren't a substitute. Spike A (README quality calibration) is the one still clearly relevant post-shelving — it directly validates the "does README comprehensiveness correctly outweigh raw stars" judgment the product now leans on entirely, with no historical fallback. Spike B (dependency data source) inherits `DependencyMap`'s status above. Spike C (intent classification) stays independently relevant regardless.
